# Checkpoint 007 — Plan for inspection findings 1 and 4

## Status
Planning complete; implementation requires product/architecture approval because this changes MCP runtime state ownership and workstream persistence paths.

## Goal
Close inspection findings 1 and 4 so an English session consumes only English MCP data and can create, read, update, present, and replay only English workstreams.

## Section 1 — Full English MCP corpus and runtime

### Required design
Replace language-neutral module globals with a `DatasetRuntime` registry keyed by normalized locale and dataset version. Each runtime owns:

- event projection and event-by-ID indexes;
- location and entity metadata;
- area aliases and bilingual query aliases;
- fusion/context indexes;
- semantic index instance and locale-specific cache directory;
- source paths and startup validation results.

The locale on every MCP call selects one complete runtime before tool logic executes. Omitted or invalid locale remains Hebrew for backward compatibility. English must fail closed when a required English asset is absent or contains Hebrew; it must never fall back to Hebrew data.

### English asset set
For active v2.1, create, deploy, and validate English variants for every file read by MCP behavior:

- `serbia_kosovo_events_projection_v2_1.en.csv`;
- `serbia_kosovo_locations_v2_1.en.json`;
- `serbia_kosovo_entities_v2_1.en.json`;
- English UAV observations if any tool or derived projection reads the UAV JSONL directly;
- any full raw CSV/JSONL that is reachable by runtime or diagnostic APIs.

Files that are evaluator-only or unreachable from production tools may remain source-language data, but they must be explicitly classified and excluded from the English runtime manifest. A manifest-driven startup check should make the distinction auditable.

### Execution slices

1. Inventory every runtime file read and classify it as tool-visible, derived-only, evaluator-only, or unused.
2. Extend deterministic English generation to all tool-visible assets; reject residual Hebrew and preserve identifiers, timestamps, coordinates, and row relationships.
3. Introduce `DatasetRuntime` and route all retrieval, resolution, aggregation, fusion, health, and semantic operations by locale.
4. Build separate semantic caches under `<semantic-root>/<dataset-version>/<locale>` and prove alternating locale calls cannot reuse the other locale's index.
5. Deploy English assets to the MCP data root, restart both MCP consumers, and scan every English tool payload.

### Acceptance criteria

- All MCP schemas accept `locale: he|en`; English agent calls include `locale=en`.
- Every English tool payload contains zero Hebrew characters in user-visible fields.
- English entity/location/event identifiers and relationships match Hebrew source cardinality and keys.
- Missing or invalid English assets produce a clear availability error, never Hebrew fallback.
- Hebrew behavior and omitted-locale compatibility remain unchanged.
- Alternating `he → en → he` semantic and exact queries show no cache/data contamination.
- Runtime health reports the selected locale, exact source paths, dataset version, checksums, and semantic-cache namespace.

## Section 4 — Locale-isolated workstreams

### Required design
Use separate physical workstream roots:

- `/opt/serbia-poc-ui/workstreams/v2_1/he/`
- `/opt/serbia-poc-ui/workstreams/v2_1/en/`

Persist a required `locale` in every newly created workstream. All list, get, create, update, archive, proposal, artifact, playback, and presentation operations resolve their path from the normalized request/session locale. A workstream ID found only in another locale returns not found and is never projected across languages.

Existing untagged/shared workstreams remain Hebrew-owned. The English store starts empty. There is no automatic migration or translation; an explicit future copy/translation workflow would be a separate capability.

### English write contract
For English workstreams, reject Hebrew characters atomically in user-visible persisted fields, including:

- title and objective;
- participant `display_name` and `role`;
- assignment responsibility;
- artifact title, summary, assessment, rationale, and recommendation fields;
- activity/attention text and presentation labels generated by the server.

Identifiers, source references, enum/status values, timestamps, and coordinates remain language-neutral.

### Execution slices

1. Add locale-aware path resolution and explicit locale persistence, preserving Hebrew fallback for untagged legacy records.
2. Propagate locale through every workstream HTTP route, investigation context, MCP proposal handoff, playback update, event/target resolver, and UI request.
3. Add English defaults for system participants and roles and English-only write validation across nested workstream/artifact structures.
4. Add isolation and lifecycle tests, then deploy with a rollback backup of the shared workstream directory. Initialize English empty; do not translate or copy records.
5. Run English create/update/archive/playback/presentation smoke tests, remove smoke data, and verify both stores return to their intended final state.

### Acceptance criteria

- English-created workstreams are stored only under `/en/`; Hebrew-created workstreams only under `/he/`.
- English list/get APIs never return Hebrew-owned or legacy shared workstreams.
- English workstreams support create, update, archive, artifacts, proposals, playback updates, and presentation without Hebrew leakage.
- Hebrew text in protected English fields is rejected without partial writes or revision changes.
- IDs cannot be used to cross locale boundaries.
- Existing untagged workstreams continue to appear only in Hebrew mode.
- English UI and API payload scans return zero Hebrew characters.
- Backup/reset/restore administration is locale-scoped.

## Risks and mitigations

- **Hidden globals:** use a runtime object passed/selected at the tool boundary and prohibit direct locale-neutral cache access.
- **Semantic cache collision:** include dataset version, locale, source checksum, and embedding backend in cache identity.
- **Partial English assets:** validate the complete manifest before serving any English call.
- **Cross-locale workstream lookup:** require locale-scoped paths before ID resolution; do not globally search by ID.
- **Nested text leakage:** validate the complete candidate document before the atomic write.
- **Legacy compatibility:** classify untagged workstreams as Hebrew and retain omitted-locale Hebrew behavior.

## Rollback
Keep current Hebrew MCP paths and the pre-split workstream directory as dated rollback artifacts. Roll back code and service configuration together; never merge the two locale stores during rollback.

Approve the architecture and execute Section 1 first, then Section 4. Section 4 depends on the locale contract and English resolver behavior established by Section 1.
