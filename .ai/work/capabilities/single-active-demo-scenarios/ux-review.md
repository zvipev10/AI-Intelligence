# UX review

Status: Draft recommendations, pending review in #68.

Keep one stable URL. Clearly display active demo name, region and data time range; do not expose internal file paths or service details to analysts. No analyst-facing switch control in the MVP; the operator switches between demos.

During a switch: stop accepting new analytical work, present a brief maintenance state, retain the analyst's old-scenario view as stale/read-only until refreshed, and explain that a refresh is required. An old tab must never submit Kosovo context to Syria. The server enforces identity checks even if a browser misses the notice.

Queue: distinguish queued from running, show a useful waiting state and allow cancellation. Background updates may wait behind direct questions. Empty or incompatible datasets show an explicit error, never a Kosovo fallback. Successful activation shows the selected scenario, while switching failure shows that the prior demo was restored or that maintenance continues.

Reopening Kosovo preserves its investigations and history. Reset is a separate deliberate action. A Syria agent can share the role name but must use Syria-specific context and state. Prompt samples and map labels are profile content, not hardcoded product copy.

Review assumptions: maintenance interval acceptable, operator-only switching, preserve-state default. No new full UI design is required for the planning task.
